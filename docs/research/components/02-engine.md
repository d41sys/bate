## Gaps, most important first

1. **The bot cannot see images.** A photo or screenshot reaches it only as a path; `read` returns garbage text for it and Telegram photos are refused. Copy pi: `read` returns image bytes, resized, as an attachment (`p/coding-agent/src/core/tools/read.ts:233-239`, `p/ai/src/types.ts:446-450`); for sent files also nanobot `nanobot/agent/context.py:336-347` and Hermes `agent/image_routing.py:1-8` (vision model or text description). Change: `agentcore/src/tools.rs` (`read`), `agentcore/src/model.rs` (image parts for both APIs), `agentcore/src/session.rs` (replay, size count), `appd/src/channels.rs` (accept photos). Size: days. Not verified: that the ChatGPT route accepts images from Bate's registration.
2. **The model does not know today's date.** Routines, "tomorrow", "this Monday" all depend on it. Copy omp: date and cwd on the first user turn of each request so the system prompt stays stable (`p/coding-agent/src/session/date-cwd-reminder.ts:1-14`), or OpenClaw's per-turn runtime context with date and time zone (`docs/concepts/system-prompt.md:212`). Change: `agentcore/src/turn.rs` (`turn`, `ask_model`). Size: hours.
3. **Compaction uses a fixed 32,000-token window and has no overflow recovery.** A long-window model is summarised far too early; a small local model can overflow and fail the turn. Copy pi: window from the model, trigger at window minus a reserve, retry once after a context-overflow error (`p/coding-agent/src/core/compaction/compaction.ts:126-130,269`, `agent-session.ts:3105-3177`); keep about 20,000 recent tokens instead of 4 messages (`compaction.ts:129`). Change: `agentcore/src/turn.rs`, `main.rs` (`begin_turn`), the `token` answer in `proto`, `appd/src/core.rs`. Size: 1 day.
4. **No limit on steps or repeated calls.** A routine that loops runs until someone aborts it; `schedule.rs` has no deadline either. pi and omp have no limit, so copy the bot apps: OpenClaw repeat guard (third identical call gets a note, twentieth ends the turn, `docs/gateway/config-tools/built-in-tools.md:75-77`) and a cap (nanobot 200 `nanobot/config/schema.py:182`, Hermes 500 `cli-config.yaml.example:1238`). Change: `agentcore/src/turn.rs` loop; end as `TurnEnd::Error` with a message. Size: hours.
5. **No web search or page fetch tool.** The bot must drive a browser to read a page or search. Copy nanobot's `web_search` and `web_fetch` (`nanobot/agent/tools/web.py:281,1173`) or, on the ChatGPT route, Hermes' swap to the server's own `{"type": "web_search"}` (`agent/transports/codex.py:244-256`; whether Bate's sign-in may use it: not verified). Change: `agentcore/src/tools.rs`, `turn.rs`, `model.rs` (`responses_body`). Size: 1 day.
6. **A failing build loses its error.** `run` keeps the first 64 KiB and drops the rest, so the error at the end of a long log never reaches the model. Copy pi: keep the tail, and save the full output to a file the model can read (`p/coding-agent/src/core/tools/truncate.ts:163`, `bash.ts:58,67`). Change: `agentcore/src/tools.rs` (`capture`). Size: hours.
7. **Nobody can send a message while the bot works.** The engine has `steer`, but the window blocks sending while busy and channels answer "busy". Copy pi: send as `steer` when busy, and keep a follow-up queue for after the turn (`p/agent/src/agent.ts:149,308-313`); Hermes shows the same as `/steer` and `/queue` (`hermes_cli/commands.py:145-150`). Change: `window/ui/src/Chat.tsx`, `appd/src/core.rs` (channel path). Size: hours for steer from the window, 1 day for a queue.
8. **The ChatGPT route drops thinking and token counts.** Reasoning is neither shown nor sent back; usage is never read, so no per-turn tokens and compaction counts by bytes. Copy pi's Codex route: `include: ["reasoning.encrypted_content"]`, read `response.reasoning_summary_text.delta`, keep reasoning items in the message, read `response.usage` (`p/ai/src/api/openai-codex-responses.ts:575-583`, `openai-responses-shared.ts:633-640,677-697`); for chat servers `stream_options.include_usage` (`openai-completions.ts:827`). Change: `agentcore/src/model.rs`, `turn.rs`, `session.rs`, `proto` (a usage event), `appd/src/store.rs`. Size: 1 day.

Not in the top 8: parallel tool calls (days; all reads are asked first, one at a time, by design of one open `question`, so low value), several edits per call and fuzzy matching in `edit` (hours; pi `tools/edit.ts:19-37`, `edit-diff.ts:245`).

## Where Bate is ahead or right to differ

- Unfinished tool calls are written to the session as real "Interrupted" results and shown in the window `session.rs:631-651`, `main.rs:197-213`. pi only fills a placeholder when it builds a request (`p/ai/src/api/transform-messages.ts:179-196`); omp adds an aborted message after a recorded exit (`docs/session.md:339`).

- A `read` and every changing action ask first with the exact target `turn.rs:514-523`; nightly runs with `approvalPolicy: never` (`README.md:17`). Whether pi and the other apps ask: not checked here (permissions belong to another group).
- Tests drive the real binary over the real protocol with byte-exact model bodies `engine.rs:46-50,1255-1334`; equal in strength to Hermes' loopback server (`tests/fakes/fake_llm_provider.py:1-9`) and wider in provider quirks than the stubs in pi, omp and nanobot.
- A chat message during a turn is answered "busy" instead of queued: the code's reason is "One at a time, as for a webhook: whoever wrote should hear it now" (`appd/src/core.rs:2145`). That covers channels; the window case (gap 7) has no stated reason.
