## Where Bate is ahead or right to differ

- Secrets: Keychain for every key and token, with a read-back check before the old copy is blanked and `secure_delete` on (`appd/src/store.rs:250-256,272`); tests use their own keychain file (`appd/tests/service.rs:162`). Others keep `0600` files (pi `auth-storage.ts:36-37`, omp `sqlite-credential-store.ts:602`, Hermes `config.py:501-508`) or plaintext config (nanobot, OpenClaw).
- Who may talk to the service: the socket is `0600` in a `0700` folder, and the peer must be the same user and, if signed, the same certificate (`appd/src/clients.rs:54,59`; `PROTOCOL.md:338`). OpenClaw and omp rely on bearer tokens (`docs/gateway/index.md:76-77`; `docs/auth-broker-gateway.md:9`).
- Prompt ledger: `uncertain` is its own state, written before send, and tested with SIGKILL (`appd/tests/service.rs:359-390`). OpenClaw says its answer "confirms acceptance, not completion" and has no such state (`rpc-session-control.md:35`).
- Planned restarts never cut a reply: the update waits until no bot has a turn in flight (`PROTOCOL.md:350`). OpenClaw and Hermes document restart recovery because their restarts interrupt work (`docs/gateway/restart-recovery.md:11`; `gateway-session-lifecycle.md:308`).
- Engine in its own sandboxed process, per bot (row 1): reason is in `PROTOCOL.md:7,246`; the in-process agents of OpenClaw, Hermes and nanobot cannot give an OS-level folder limit to each bot.
- Test isolation: a custom `APPD_HOME` gets its own launchd label and Keychain service (`appd/src/launch.rs:42-50`; `appd/src/keychain.rs:1-3`); nobody else in this set was seen doing both.
- No hand-edited config file (row 10): nightly and CK desktop, the other GUI apps, also keep settings in a database or server. No Bate doc states this as a decision, so the verdict stays "no reason found".
