## Where Bate is ahead or right to differ

- **OAuth tokens in the Keychain, never in the engine.** Bate: Keychain item per sign-in, engine given a loopback URL, proxy adds the token (`PROTOCOL.md:482`; `appd/src/proxy.rs:1-4`). pi, Hermes and nanobot keep a 0600 file (pi `src/core/auth-storage.ts:37`; Hermes `tools/mcp_oauth.py:393-408`; nanobot `mcp_oauth.py:101-102`), omp and OpenClaw a database (OpenClaw: no encryption found). Only nightly (`safeStorage` plus a loopback proxy, `integrations.md:134-156`) and CopilotKit (encrypted vault) are comparable. Bate also refuses redirects and any non-https sign-in address (`oauth.rs:62-71,81-89`).
- **Every connector call asks by default**, as a permission kind with "Always" per tool (`PROTOCOL.md:77,84,269`). pi leaves it to extensions (`docs/mcp.md`, section "Permissions"), Hermes defaults to `trust: full` (`tools/mcp_tool.py:573`), nanobot has no gate found.
- **Memory and skill folders are read through a held-open directory, never following links** (`appd/src/memory.rs:1-3`; `agentcore/src/memory.rs:30-45`; tests at `agentcore/src/memory.rs:80-131`). The other apps' memory loaders that I read (OpenClaw, Hermes, nanobot) do not describe link or hard-link handling; OpenClaw has symlink containment for skill roots only (`docs/tools/skills.md:~423`).
- **ACP as the bot's engine with Bate's permissions on top** (`PROTOCOL.md:421-423`) exists in none of pi, omp, nanobot, CopilotKit as a client; it matches nightly and Hermes.
- **Per-bot connectors** match nightly's per-agent access (`docs/architecture/integrations.md:103-108`) and suit a bot app: the terminal apps use one global file because one person drives one agent.
