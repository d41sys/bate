## Notes

- **Commits:** read from `.git/refs/heads/main` and shortened to 8 characters; both were later confirmed with `git rev-parse` (see the README).
- **pi has more than one product:** the `pi` CLI is the user-facing coding agent. `apps/p2` is a separate server/web-UI prototype. Its own README says it will be removed (`apps/p2/README.md:3-5`). `apps/p3` is its headless successor. `apps/p2-mac` is a Swift shell that wraps p2's web UI and needs a p2 checkout. Voice and Discord exist only in p2, not in the CLI.
- **p2/p3 do not use the CLI's agent loop:** they run `pi-durable`'s own harness on `pi-chord` (SQLite, WebSocket, plugins). Rows 5, 6 and 8 for p2/p3 differ from the CLI.
- **omp is a derivative of pi, not a thin fork:** it kept the `pi-*` names and loop skeleton but has its own provider clients, MCP/ACP code, TUI renderer and native layer. Most pi → omp differences sit in the Rust `crates/` listed in row 8. Of the 12 crates, `pi-natives` is the single cdylib Bun loads; the other 11 are plain libraries linked into it (`crates/pi-natives/Cargo.toml:11,41-54`). Seven vendored patched crates sit under `crates/vendor/` (`Cargo.toml:19-25,38-57`), e.g. a patched `napi` and `grep-searcher`.
- **Optional dependencies:** `fastembed` and `onnxruntime-node` are optional peer dependencies of mnemopi (`packages/mnemopi/package.json:52-56`). pi's `@earendil-works/gondolin` VM sandbox is only an example extension, not part of the CLI (`packages/coding-agent/examples/extensions/gondolin/package.json:17`).
