## Notes

- **ZeroClaw ships many shapes:** one repo holds the daemon, a Tauri tray app, a ratatui TUI, a React dashboard, a relay and MCU firmware. Many features are optional Cargo features (`Cargo.toml:290`, `:303`). A given release archive carries only the `dist_extra_features` set (`Cargo.toml:247`). `Cargo.toml:~341-387` lists channels that are off by default.
- **ZeroClaw's desktop app is a thin shell:** it loads the daemon's dashboard URL (`apps/tauri/src/lib.rs:166`). Its two native capabilities, AppleScript and screenshot, are documented as unreachable from gateway-served content (`apps/tauri/src/capabilities/mod.rs:1-3`).
- **PicoClaw has two binaries:** `picoclaw` (CLI and gateway) and `picoclaw-launcher` (web UI, tray, and the gateway's parent process). The launcher's tray needs CGO on some targets (`Makefile:136` sets `CGO_ENABLED=1` for the macOS launcher; `web/backend/systray_stub_nocgo.go` exists). Browser automation exists only as a skill that needs the heavy Docker image (`workspace/skills/agent-browser/SKILL.md:11`). Isolation covers child processes only.
- **NanoClaw's agent loop is Claude Code's, not NanoClaw's.** In trunk the host handles routing, mailboxes, containers and delivery (`src/router.ts`, `src/container-runner.ts`, `src/delivery.ts`). It is also thin on channels: only `cli` is in trunk; Telegram, Discord, Slack and the rest are copied in by skills. `@anthropic-ai/sdk` is declared but not imported in non-test source.
- **NanoClaw's credential-gateway row names OneCLI** because the skill installs it. The host code reaches it through a provider registry, so the gateway can be swapped (README `:97`).

Not checked: exact line numbers for a few `Cargo.toml` feature blocks (marked `~`), and GoReleaser lines marked `~`.
