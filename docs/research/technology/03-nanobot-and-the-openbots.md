## Notes

- **CopilotKit/OpenBot, backend missing:** the server (Hono), `agent-computer` and `supervisor` source are not in this repo. Compose pulls the published `ghcr.io/copilotkit/openbot` image, and docs cite `server/src/...` files that don't exist here (`docker-compose.yml:64-87`). Rows 6, 7, 9, 10, 11, 13 for built-in Bots therefore rest on docs and compose, not on code. CopilotKit Intelligence (threads, memory) is also separately licensed and not in the repo. The `agent-*` folders hold only AG-UI harness wrappers.
- **CopilotKit/OpenBot, two UIs:** the Tauri `desktop/` UI is only a setup and launcher window that installs Docker or Podman and starts the stack. The actual workspace UI is `app/` on 3001 or 3010. Playwright is a setup-helper dependency only, not Bot browser control.
- **nanobot, optional pieces:** channel libraries (telegram, discord, slack, matrix, etc.) are optional, installed from each channel's `manifest.py`, and not in core `pyproject.toml` (`Dockerfile` comment). The built WebUI (`nanobot/web/dist`) is git-ignored and bundled at build time (`pyproject.toml` `[tool.hatch.build]`). `cli/desktop_target.py` talks to an external Desktop app that is not in this repo.
- **nightly-labs, engines are not in-repo:** it runs vendor CLIs it downloads and pins (`native-runtime.lock.json`), so most "agent" behaviour lives in those binaries. The lock's Claude pin (0.3.263) differs from the npm pin `@anthropic-ai/claude-agent-sdk 0.3.309` (`package.json:518`). Linux has no process sandbox in OpenBot's own code. `@anthropic-ai/sdk` is listed but no import was found.
- **Citations:** rows citing only a file or section (no `:line`) are marked as such.

Skipped: I did not read the nightly-labs `remote/` Signal code beyond its manifest and `telegram.ts:97`. I did not check Slack library use, the Elysia route list, or the CopilotKit SSE wire format.
